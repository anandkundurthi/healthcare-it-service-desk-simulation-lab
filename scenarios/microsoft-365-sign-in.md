# Scenario: Microsoft 365 Sign-in Support

## Scenario
A fictional employee reports repeated sign-in prompts when opening a Microsoft 365 application.

## Intake questions
- Which application is affected?
- Does the issue occur in one application or multiple Microsoft 365 services?
- When did it begin?
- Is there an exact error message or error code?
- Can the user access the service through an approved browser?
- Are other users reporting the same issue?

## Safe first-level checks
1. Confirm the affected application and scope.
2. Ask the user to read the error message; do not ask them to share a password or MFA code.
3. Check whether the device has network connectivity using approved checks.
4. Confirm date and time are reasonable if this is within your support scope.
5. Follow the organization's approved sign-in troubleshooting article.
6. Do not bypass MFA, collect credentials, or change account security settings.

## Possible routing
- One user/account-specific issue: identity or account support.
- Multiple users or broad service issue: service health / Microsoft 365 support path defined by the organization.
- Device-specific application issue: desktop/application support.

## User update example
"We have recorded the repeated sign-in prompt and are checking whether it is limited to this application or account. Please do not send your password or verification code. We will update you after the next check."

## Practice outcome
Document only the checks actually performed and the resulting observations.
